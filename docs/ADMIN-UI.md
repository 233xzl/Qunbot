# 本地管理台

2026-11-17：运行控制、配置热更新与首版 Web UI 已接通。管理台默认位于 `http://127.0.0.1:8765`，使用独立管理密钥登录。

## 启动

在安装后的环境运行：

```powershell
qunbot admin init --instance data/my-agent
qunbot admin serve --instance data/my-agent --demo --port 8765
```

`init` 创建实例配置与随机管理密钥，密钥只在终端显示一次，请保存。打开浏览器，输入密钥登录。源码环境也可使用 `.venv/Scripts/group-agent.exe` 或 `.venv/Scripts/python.exe -m group_agent.app`。

`--demo` 使用实例下独立的 `demo/` 数据库和媒体目录，固定假模型、关闭 QQ 连接及发送；可在总览启动引擎并提交模拟请求。它走正常的准入、调度、模型与账本流程，费用为零。模拟模型返回固定文本；人设采用情况可在请求详情的配置版本中核对。

前台连接真实 QQ 时省略 `--demo`。首次启动管理台时引擎保持停止，在总览的首次配置引导中依次设置账号、模型、凭据、搜索、人设与预算，保存并应用后再点击“启动 Agent”。界面里的“停止”只停止 Agent，管理页面仍可访问。

端口可通过 `--port` 修改；首版 `--host` 支持 `127.0.0.1`、`localhost`、`::1`。单进程、单 worker 运行。前端为随 Python 包交付的 HTML/CSS/JavaScript，最终用户不需要 Node 或前端构建工具。

## 后台部署与升级

在仓库根目录使用 `uv run qunbot`，或在 Windows 使用 `.\qunbot.cmd`。下表中的 `data/my-agent` 代表已初始化的实例目录。

| 操作 | 命令 |
| --- | --- |
| 启动后台 WebUI | `uv run qunbot admin start --instance data/my-agent` |
| 查看后台服务状态和监听地址 | `uv run qunbot admin status --instance data/my-agent` |
| 升级后重启 | `uv run qunbot admin restart --instance data/my-agent` |
| 关闭后台服务和 Agent | `uv run qunbot admin stop --instance data/my-agent` |

**升级。** 更新代码后执行 `uv sync --locked`，再执行表中的 `restart`。管理台会记录 Agent 状态，正常关闭旧服务并加载新版。此前运行中的 Agent 会自动启动，已暂停回复的 Agent 会恢复到暂停状态，已停止的 Agent 保持停止。重新登录 WebUI 后，可在总览确认 Agent 状态与网关连接。

**端口与模式。** 首次后台启动默认使用 `127.0.0.1:8765` 和真实模式。`start` 和 `restart` 会沿用上次后台启动的参数。要更改端口，先执行 `stop`，然后在 `start` 命令后加 `--port 8766`。同样可以用 `--demo` 切换到模拟模式，用 `--no-demo` 切回真实模式。切换模式后，在 WebUI 手动启动 Agent。

**从前台迁移。** 在旧 WebUI 中停止 Agent，等总览显示已停止，再到运行 `admin serve` 的终端按 `Ctrl+C`。用原实例目录执行 `admin start`，如需沿用自定义端口或模拟模式，首次启动时带上相应参数。登录后点击“启动 Agent”即可恢复运行。若启动失败，可在实例目录的 `private/background/service.log` 查看原因。

## 密钥与连接凭据

- 管理密钥：独立于模型和 SnowLuma 凭据；后端仅保存验证摘要。登录换取最长 12 小时的服务端会话，退出即失效，服务重启需要重新登录。
- 重置管理密钥：`qunbot admin reset-key --instance data/my-agent`。新密钥在终端显示，旧会话在下一请求时失效。
- 模型和网关凭据：新实例预置 managed 引用。在系统设置的“更新管理型凭据”中选择引用名称、填写值。SnowLuma 需要 `SNOWLUMA_WS_URL` 和 `SNOWLUMA_WS_TOKEN`；其余名称与模型/搜索表单中的引用保持一致。
- 外部凭据：引用来源设为 file/env，值由外部维护；修改后点击“重新加载凭据”。模型/搜索客户端更新后供新请求使用，网关凭据改变需停止引擎并重新启动。
- 浏览器只接收凭据来源与配置状态；原始密钥不返回、不写入 URL 或 localStorage。

## 页面与配置应用

左侧栏分为监控、配置、管理。监控区有“总览”和“请求与日志”两个入口。总览显示引擎与网关状态、区间用量和最近五条请求，请求与日志页提供筛选、分页、对话详情和运行诊断。

人格、模型、供应商连接、搜索、预算、访问控制、运行限额、保留策略都通过配置服务保存。常用字段直接显示，更多参数在折叠区。配置操作分两步：

1. **保存草稿**：完整校验并保存，不修改运行对象。
2. **保存并应用**：显示字段差异与生效方式，确认后发布并等待运行端采用。

| 修改 | 生效方式 |
| --- | --- |
| 人格、模型、搜索、调用价格、请求期限与上下文 | 新请求采用快照；在途请求保留原配置与客户端 |
| 预算、访问权限、并发、限速、关闭联网/发送 | 下一次相应操作检查采用新策略，保留消费、预留和队列 |
| 保留策略与清理间隔 | 下一轮维护采用；仍有活跃请求时跳过本轮清理 |
| 机器人身份、数据目录、网关连接、首次开启发送能力等 | 保存为待维护版本，停止引擎后重新启动采用 |

混合修改包含维护项时，整版待维护。应用失败会显示原因，客户端准备失败时旧版本继续运行。配置回滚走相同的应用路径，凭据和累计消费不随配置回滚。被启动参数固定的值会在页面标注；模拟模式固定关闭发送与联网。

“请求与日志”提供每个 run 的结构化诊断。存储页提供三类数据库大小、清理预览和停止引擎后的数据库快照；快照不包含媒体或凭据。知识内容编辑、完整备份恢复与连续进程日志流可继续在这些服务上扩展。

## 群个性化与分群观测（2026-11-18）

在侧栏打开“群个性化”，选择已收信群聊并开启个性化。可单独覆盖人格等提示词、回答 / 判断 / 备用模型，以及本群每日限额。先在“模型与供应商”中配置连接和模型别名，再为群选择对应别名。每次请求的搜索与网页读取上限可分别填写，输入框显示继承的全局次数。留空继承，填 0 关闭该项。应用后新入队的请求使用新上限，已入队的请求继续使用原值。全局联网开关对所有群生效。关闭开关会保留填写的覆盖值，重新开启时可继续使用。

点击“保存并应用”并确认差异。新入队的请求采用新提示词和模型，已入队的请求按原快照完成。预算在下一次准入或调用检查时生效，修改限额和回滚都保留已有消费与预留。

所有群共同使用全局日预算。若全局设为 ¥18、A 群另设 ¥5，A 群消费 ¥4 时按默认阈值关闭联网，到 ¥5 后仅响应主人。其他群继续使用剩余全局预算。全局预算触发降级或限额时，对所有群生效。每日按北京时间结算，账号免费查询次数仍由账号总账统一核算。

“请求与日志”可按群筛选，总览的消费趋势可按群聊展示。请求详情显示当时的配置版本、本群覆盖项、调用明细和触发降级或拒绝的预算来源。升级消息库到 v11 时，账本根据保留的请求回填群号，已清理请求且无法归属的消费列入“未归属”，计入全部群的总费用。请求数按保留的请求统计，费用按账本统计。

在独立模拟实例中可从总览分别输入两个群号发起试聊，再按群核对请求与模型记录。模拟调用费用为零。

## 代码入口与验证

`runtime.py` 提供 `RuntimeController.start/stop/pause/resume/status/apply_config`；CLI 与管理 API 共用它。`serve.py` 使用退出栈管理启动和关闭资源；`Orchestrator` 在 run 入队前捕获限制、人格与客户端引用，完成后释放引用并关闭不再使用的模型客户端。

`admin/server.py` 提供认证、配置、控制和查询接口；`admin/static/` 为静态页面。配置与提示词仍由 `ConfigService` 管理，不新增管理数据库。界面使用 5 秒轮询。

验证覆盖密钥登录/退出/重置、来源校验、配置冲突、热更新、准备失败、撤权取消、在途客户端释放、账单连续性、启动失败释放、实例锁与停止后重新启动。浏览器验证了登录、模拟请求、人格修改与采用提示，以及窄屏侧栏。

## 监控区（2026-11-19）

### 总览与完整记录

侧栏“监控”收为“总览”和“请求与日志”两个入口。总览保留运行状态和启停操作，承接原“用量与账单”的消费、请求数、Token 和模型用量。页面下方显示最近五条请求日志，按时间倒序排列。“查看全部”进入“请求与日志”，可按群、状态与时间筛选，分页查看全部保留记录。两处使用同一套请求摘要和详情。

### 消费趋势

图表提供两个可组合的选择器。展示方式可选“合计”“按模型”“按群聊”。按模型时用实际模型或工具后端名称作图例，标明对话（含判断、回答及备用调用）、搜索或获取。同一后端承担不同用途时分别列出。按群聊时用群名作图例，以群号作为内部分组键，同名群分别统计。无法关联群的账目列入“未归属”。

时间范围可选今天、昨天、近 24 小时、近 7 天、近 14 天、近 30 天，默认近 7 天。今天和昨天按北京时间的自然日计算，近 24 小时从当前时刻向前滚动，多日范围含今天。单日和近 24 小时按小时展示，多日按日展示，空时段补零。切换范围时同步更新区间费用、请求数和 Token；“今日消费 / 日预算”保留当天口径并明确标注。

`/api/usage` 接受时间范围和分组方式。费用取消息库 `usage_ledger.cost_cny`，按每条调用的 `created_at` 落桶，结合 `provider`、`model`、`service` 归类。旧记录缺少用途时优先用可识别的 `task` 映射，剩余列入“其他”。请求数按 `runs.created_at` 计数。各分组费用相加应等于同一区间的合计。

### 从请求摘要读到一次对话

列表字段为消息摘要、群名、时间、状态、耗时、当次费用。摘要取触发消息正文的前五个可见字符，超长追加“…”；短消息完整显示。忽略用于唤起机器人的 @ 和回复引用标记，纯图片等消息显示“[图片]”等类型。点击摘要进入对应请求，即使两条摘要相同也能分别打开。`run_id` 仅用于关联和跳转。

详情按对话顺序显示发起成员（优先群名片，其次昵称）、完整触发消息、Bot 最终回复和发送状态。消息通过 `runs.message_seq → messages.seq` 读取，回复通过 `run_id → outbound` 读取 `answer` 或 `new_version` 的正文。忙碌提示单独标明，已生成但未发送的回复标明发送状态。被拒绝且没有回复时显示“已拒绝 · 无回复”。已撤回或清理的正文显示对应占位。默认详情省略中间过程和原始 JSON；完整记录页保留按需展开的诊断入口。

当次费用按 `run_id` 汇总该请求全部已入账调用，包含对话、搜索和获取。列表与详情复用同一金额，运行中的记录标为“截至当前”。已知零费用显示 ¥0，可计费的小额保留足以区分零的精度。历史记录无法核实时显示“费用未知”。

### 群名与成员名的数据来源

消息、回复和费用已有本地关联键。引擎启动时将消息库升级至 v12。v13 从保留的群消息建立已收信群目录，在线引擎在连接后和运行期间同步群名与成员资格。收到新请求时保存当时的群名片或昵称。管理页批量读取本地数据，离线也能浏览。历史群优先使用已知群名，缺失时显示“未知群聊”；发起人名称缺失时显示“未知成员”。群名暂缺与账目未归属分开处理。

实施顺序与验收项见仓库根目录的 [tasklist.md](../tasklist.md)。

## 群选择、单群启停与设置文案（2026-11-19）

### 从收到过消息的群聊中选择

“群个性化”改用群名选择器。机器人收到某群的第一条普通群消息，该群就进入候选目录，无需有人 @ 机器人、创建请求或产生费用。目录按机器人账号和群号保存群名、最近收信时间及成员资格，遵守现有屏蔽和采集策略。升级时从保留的群消息补录历史候选。请求与账单页继续按各自保留的历史记录查询。

收到退群或被移出的通知时，核对离群成员是否为机器人本人，确认后从可配置列表移除该群。网关重连时用成员资格查询校准离线期间的变化。查询超时标为“待确认”，保留历史配置，待恢复连接后再校验。重新入群并再次收到消息时关联原配置。服务端在新增配置或启动该群时校验候选资格。

选择器展示群名，重名时附群号尾号，仍重名时显示足以区分两群的信息。群名尚在获取时展示“群名待同步”和尾号。没有候选群时提示“机器人收到群消息后，可在这里选择群聊”。已离群的旧配置保留，历史日志仍可查询。

### 在全局运行期间控制单群回复

群详情提供两个独立操作。“本群回复”控制该群是否处理请求，“使用本群个性化设置”控制人格、模型和预算是否覆盖全局配置。停止本群回复后继续按采集策略接收群消息，保留个性化设置。

| 全局状态 | 群页面行为 | 后端行为 |
| --- | --- | --- |
| 运行中 | 可启动或停止本群回复 | 启动前检查群资格、访问策略和全局状态，停止只作用于所选群 |
| 已暂停 | 显示“全局回复已暂停”，禁用启动 | 拒绝启动本群，全局恢复后按各群保存的开关继续运行 |
| 已停止、启动中、停止中或启动失败 | 显示全局状态，禁用启动 | 拒绝启动本群，由总览控制全局引擎 |

现有群和新发现的群默认跟随全局，管理员明确停用的群在全局重启后仍保持停用。启动本群继续遵守全局发送开关、访问控制和预算。停止本群即时生效，撤销该群排队请求，阻止在途请求继续发起调用或发送新回复。已发出的调用按实际结果结算，其他群继续运行。群启停独立于配置草稿，在后端执行并回显实际状态。

### 设置字段与本地化文案

为每个内置设置建立“完整配置路径 → 稳定文案键 → 语言文本”的对应关系。`schema` 描述字段类型、可选值和生效方式，简体中文语言文件提供标签、说明、单位和选项名称。动态模型、连接或群的配置使用路径模板。完整路径可以区分不同页面里的同名字段，例如消息库与知识库各自的 `db_path`。表单保存原始配置路径和枚举值，管理员自定义的名称原样显示。

| 配置字段 | 中文界面文案示例 |
| --- | --- |
| `retention.max_messages_per_group` | 每个群最多保留的消息数 |
| `serve.self_sync_interval_s` | 机器人消息同步间隔（秒） |
| `collection.max_concurrent_downloads` | 同时下载的图片数上限 |

覆盖普通和高级设置、添加字段弹窗、群覆盖项、枚举选项、保存差异与校验提示。同一字段在各入口复用同一译名。按页面盘点现有 `labels[key] || key` 和直接展示的变量名，给所有内置字段补齐中文。后续语言包按同一组文案键添加，缺译回退到简体中文。用测试语言包验证切换语言后的显示、保存及重载。

设置文案位于 `src/group_agent/admin/static/zh-CN.json`。新增语言时，在同目录放入以浏览器语言标记命名的 JSON 文件，例如 `en-US.json`。按简体中文词表的键提供译文即可，未翻译的字段沿用中文。

## 模型与供应商（2026-11-19）

### 从供应商连接到模型用途

“模型与供应商”页先展示供应商列表。每行显示名称、协议、已配置模型数和凭据状态，提供编辑和删除。点击“添加供应商”后可选“内置供应商”或“自定义 API”。内置预设填写协议、默认服务地址和凭据字段，自定义连接则先从下拉菜单选择协议，再填写名称、基础地址和密钥。用户可为同一协议添加多个中转站。密钥沿用管理型凭据或已有凭据引用，编辑时留空表示沿用原值。

保存连接后，在该供应商下添加模型 ID、本地别名和计价信息，再从这些别名中选择回答、判断和备用模型。模型目录可作填写辅助，允许手填中转站提供的模型 ID。配置过凭据的连接标为“已配置凭据”。只有实际测试过连接才展示测试结果。删除连接时列出使用它的模型，删除模型时列出全局、群覆盖和搜索配置中的引用，引导用户先换绑。

### 协议下拉菜单与运行端

| 页面名称 | 配置值 | 接入方式 |

页面根据协议显示地址示例，保存时校验基础地址和版本。Google 的 `v1beta` 属于 API 版本，协议选项可显示为“Google Gemini（v1beta）”。配置校验、供应商连接继承、模型构造和中文词表共用同一组选项。验收以本地模拟服务实际收到的路径和请求体为准，同时核对鉴权、文本与工具结果解析、用量入账和失败后的备用模型调用。

### 退役 JEV / SystemOne

回答、判断和备用角色从现有模型别名中选择。旧版本配置按原始摘要校验，通过后按协议排除 SystemOne 模型。编辑器提示已退役的模型，下次发布时清理对应配置。历史请求、费用与回放报告保留当时的模型名称。

### 保存与替换 API 密钥

供应商和独立模型的 API 密钥使用密码输入框。提交非空新值时写入本实例的私有凭据文件，成功后清空输入框，仅回显配置状态。留空沿用当前凭据。已有环境变量或外部文件来源在首次替换时切换为该连接专用的本地凭据。配置草稿、版本、差异和日志只使用引用。服务地址可直接填写，已有外部地址引用在留空时继续生效。

在“模型与供应商”编辑窗口填写密钥并确认，点击“保存草稿”或“保存并应用”完成写入。文件位于当前实例的 `private/provider-keys.env`，由操作系统限制访问。选择“保存并应用”后，运行中的客户端采用新密钥。搜索页也可直接填写搜索服务密钥。

## 作者默认配置与合并转发

新实例采用作者本机已发布的通用人格、取证与答复规则、搜索次数、上下文和预算设置。作者预设采用每请求 3 次搜索、5 次网页读取、80 条上下文、120 秒时限、每日 20 元预算和 90% 降级阈值。正式模式启用群聊回复和处理表情。自身消息同步需先指定部署机器上的 SnowLuma 数据库路径，再开启。账号、群覆盖、凭据、模型和机器路径属于部署配置。

回答前展开本次提问、直接引用或近期相关消息中的合并转发。按节点顺序提供发言人与正文，图片遵循本次请求的附件上限。为嵌套深度、节点数和处理时间设置上限，保留已取得的部分，在请求详情记录缺失原因。用含文字和图片的直接引用、同群追问、嵌套转发和网关失败场景验收。
